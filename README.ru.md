<h1 align="center">MeshMemo</h1>
<p align="center"><strong>Сервер истории Meshtastic</strong><br>Локальный архив переписки вашей mesh-сети.</p>
<p align="center"><a href="README.md">English</a> · <strong>Русский</strong></p>

MeshMemo подключается к ноде Meshtastic по USB, сохраняет сообщения каналов
в SQLite и предоставляет веб-интерфейс для чтения чатов и управления архивом.
Облачный аккаунт, отдельный сервер базы данных и сборка фронтенда не нужны.
Интерфейс доступен на **английском, украинском и русском** языках.

**Статус: alpha / предварительная версия.** Приём по USB и админка проверялись
на Windows и Debian с LILYGO T-Beam Supreme. В радиотесте с обычной клиентской
прошивкой прошли запрос `/history 6` и получение одного сообщения на вторичном
канале. Выдача истории **выключена по умолчанию**. Проверки отображения на iPhone,
дедупликации, истории сообщений самого сервера и работы через несколько узлов
ещё не завершены. Подробности — в [текущем статусе](docs/implementation-status.md).

Версия сервера 0.1.0a8 поддерживает контракт USF2 1/4 из MeshMemo Firmware
Builder 0.1.0a2 и прежние USF1 1/2–1/3. Для T-Beam S3 Core и Heltec V3 есть
отдельные профили сборщика; аппаратная приёмка новых сборок ещё предстоит.
См. [совместимость прошивок](docs/firmware-compatibility.md).

## Возможности

- Архив текстовых UTF-8 сообщений закрытых каналов.
- До 256 каналов с ключами на сервере без расходования дополнительных слотов ноды.
- Таблица каналов, добавление и редактирование в модальном окне, отдельные настройки сохранения и выдачи истории.
- Необязательная команда `/channel add` через PKI-защищённые ЛС от разрешённых администраторов; по умолчанию выключена.
- Разделение истории по ноде, каналу и настройкам радиосети; устранение повторов пакетов.
- Чтение чатов, поиск, имена отправителей и постраничная загрузка истории.
- Статистика, проверка целостности и резервное копирование SQLite.
- Автоматический поиск USB-ноды, ручной выбор порта и переподключение.
- Настройки хранения, ограничений и экспериментальной выдачи истории по радио.
- Команда `/history <часы>`; команды не сохраняются и не попадают в ответы.
- Данные остаются на сервере, без внешней аналитики и CDN.

Личные сообщения, публичные каналы со стандартным ключом, MQTT, телеметрия,
полученная история S&F и команды `/history` и `/channel` (включая ошибочные)
не архивируются. Зашифрованные пакеты с неизвестным ключом также не сохраняются.
Во время паузы новые сообщения пропускаются; при отключении ноды возможны пробелы.
См. [архитектуру и правила хранения](docs/architecture.md).

## Быстрый запуск

Нужен **Python 3.11–3.13**. Устанавливайте из проверенной копии репозитория;
публикация пакета в PyPI не заявляется. Имя пакета и команды — `meshtastic-sf-server`.

```sh
python -m venv .venv
# Linux / macOS:
. .venv/bin/activate
# Для Windows PowerShell вместо предыдущей команды:
# .\.venv\Scripts\Activate.ps1
python -m pip install -c requirements/constraints.txt .
cp deploy/config.example.toml meshmemo.toml
# Windows PowerShell: Copy-Item deploy/config.example.toml meshmemo.toml
# Перед запуском задайте admin.password в meshmemo.toml (от 12 символов).
# Linux/macOS: chmod 600 meshmemo.toml
meshtastic-sf-server serve --config meshmemo.toml
```

Откройте **http://127.0.0.1:18765**. Во встроенном окне входа браузера укажите
логин **admin** и пароль из конфигурации. В настройках выберите автоматический
поиск USB-ноды или нужный порт, затем примените настройки подключения.
В новом архиве USB-подключение и выдача истории изначально выключены.

Порт можно задать при первом запуске:

```sh
meshtastic-sf-server serve --config meshmemo.toml --device /dev/serial/by-id/YOUR_NODE
# Windows: укажите фактический COM-порт вместо пути, например COM7.
```

При последующих запусках сохранённые настройки подключения имеют приоритет
над `--device`. Для одного архива и USB-устройства запускайте один процесс.
Для приёма сообщений сервер должен работать постоянно. Обычная прошивка
поддерживает приём; выдача истории с сохранением авторов требует специальной прошивки.

## Как запросить историю

Если оператор включил выдачу истории и установил совместимую прошивку серверной
ноды, отправьте в нужный закрытый канал обычное сообщение:

```text
/history 6
```

Это запрос сообщений за последние шесть часов — например, после возвращения
в сеть, когда нода несколько часов была выключена. Действуют ограничения сервера
на глубину истории, число сообщений и частоту запросов. Команда один раз видна
в канале, но не попадает в архив и повторную выдачу. Ответы S&F адресованы
запросившей ноде; её собственные сообщения исключаются. Если история пуста,
сервер ничего не присылает. Служебная сводка в ответ на `/history` не отправляется.

Для отправки команды патч клиентской прошивки не нужен, однако совместимость
телефонных приложений ещё требует проверки. Подробнее — в
[инструкции пользователя](docs/user-guide.ru.md).

## Эксплуатация и данные

Админка по умолчанию доступна только на **127.0.0.1:18765**. Пароль из приватного
TOML-файла обязателен для всех страниц, API, резервных копий и проверок состояния.
Для доступа по локальной сети явно настройте адрес и разрешённые хосты.
HTTP Basic не шифрует трафик: в недоверенной сети используйте HTTPS или SSH-туннель.
Это сервис для одного доверенного оператора, без отдельных ролей пользователей.

Архив и резервные копии содержат открытый текст сообщений и идентификаторы нод.
Защитите каталог данных правами ОС. Ключи каналов, автоматически прочитанные
из USB-ноды, не сохраняются. Ключи, явно добавленные в каталог сервера,
хранятся в SQLite в зашифрованном виде. Для восстановления нужен отдельный
мастер-ключ `<database>.channels.key`: он **не входит** в скачиваемую через админку
копию базы. Сохраняйте его отдельно. Бэкапы прошивки могут содержать открытые ключи
каналов и должны оставаться приватными. См. [резервирование ключей](docs/server-channels.md#key-storage-and-backups).

В [Firmware Builder](https://github.com/dmitryplohotnyuk/meshmemo-firmware-builder) 0.1.0a2 опции UA22, экранной кириллицы и тайм-аута экрана
независимы и выключены по умолчанию. Исторические скрипты `firmware/` сохраняют
прежний профиль установленной T-Beam. Установка сервера автоматически ноду не прошивает.

## Разработка

```sh
python -m pip install -c requirements/constraints.txt -e '.[dev]'
python -m pytest
node --test tests/ui/i18n.test.cjs
python scripts/release-check.py
python -m build
```

Node.js 22+ нужен только для тестов интерфейса. Для нативных C++ проверок нужны
подготовленные исходники прошивки и компилятор — см. [CONTRIBUTING](CONTRIBUTING.md).
Тесты используют искусственные данные и не открывают физические USB-порты.
Аппаратные проверки выполняются отдельно. Зафиксированные версии зависимостей
не заменяют проверку окружения на целевой ОС.

```text
src/meshtastic_sf/  логика, хранение, USB, сервисы и веб-интерфейс
firmware/          зафиксированная база прошивки, патчи и код моста
scripts/           подготовка, сборка и проверка публикации
requirements/      проверенные версии зависимостей
deploy/            примеры конфигурации и systemd-службы
tests/             Python, C++ и тесты интерфейса
docs/              инструкции, архитектура, решения и исследования
```

Каталоги `data/`, `.build/`, `.venv/`, `dist/`, кэши и отдельный репозиторий
`firmware-builder/` исключены из публикации сервера. Не публикуйте реальные
переписки, скриншоты с личными данными, ключи и резервные копии нод.
