## Что переносится в серверную сборку

| Изменение | Источник | Требование к новой сборке |
| --- | --- | --- |
| Лимит UA_433: 10 → 22 dBm | `src/mesh/RadioInterface.cpp` | Сохранить в пользовательском профиле UA22; не менять диапазон и duty cycle |
| Включение OLED_UA | `variants/esp32s3/tbeam-s3-core/platformio.ini` | Сохранить украинские/русские glyphs 10/16/24 px |
| Обработка UTF-8 префикса `0xD2` | `src/graphics/Screen.h` | Сохранить исправление `Ґ/ґ` |
| Подключение windows-build.ini | `platformio.ini` | Учесть при воспроизведении прежней сборки |
| Отключение `-flto` | `windows-build.ini`, `extra_scripts/windows_lto.py` | Сохранить рабочий Windows build path; отдельно проверить переносимость |
| Короткие Windows пути | внешний `build-tbeam-s3-core-UA22.ps1` | Учесть временный `Q:` и возврат окружения, не перезаписывать занятый диск |

UA22 меняет таблицу региона, а не сохранённый `tx_power`. В архивной верификации
UA_433: 433.0–434.7 MHz, duty 10%, limit 22; UA_868 limit 14; EU_433 limit 10.
Новая сборка не должна сама менять region/tx_power в конфигурации пользователя.
Оценка правил использования радиочастот в эту проверку исходников не входила.

Шрифты уже присутствуют в upstream; локальная правка включает их и исправляет
конвертацию, а не добавляет общий Unicode или переводит весь UI.
В старом отчёте display/font symbols подтверждены, но visual Cyrillic test
отмечен `not performed`: зрительную проверку считать незавершённой.

Важная деталь Windows workaround: Python script проверяет `os.name == "nt"`,
но `build_unflags = -flto` в подключённом INI применяется без проверки ОС.
Нельзя называть весь существующий workaround автоматически Windows-only.
При выделении переносимых профилей сохранить исходный patch как эталон,
а изменение build options проверять отдельно.

## Как объединять с S&F

Целевая пользовательская сборка: **UA22 + Cyrillic OLED + USB S&F bridge**.
Последовательность: pinned upstream → сохранённый baseline patch → новый S&F patch.
В существующий уже изменённый checkout первый patch повторно не накладывается.
Работа над S&F ведётся в отдельном checkout; прежние исходники и архивы сохраняются.

Изменений в `PhoneAPI`, `MeshService`, `Router`, `StoreForwardModule`, `GPS.cpp`
и `RTC.cpp` относительно этой базы не найдено. Прежние патчи не снимают USB
sender-блокер. OLED не меняет payload по радио. UA22 затрагивает RadioInterface,
но сохраняет duty cycle: новый pacing не должен обходить airtime ограничения.

Для публичного проекта отделять inherited custom profile от общего S&F bridge:
другие пользователи не должны автоматически получать UA22 или T-Beam OLED options.
Сам baseline patch сохранён как исторический combined diff; разделение профилей
и новый replay patch ещё не реализованы.

## Разделы памяти и размер

В старом отчёте по прошитой T-Beam зафиксированы:

- приложение: offset `0x10000`, размер раздела `0x250000` = 2 424 832 байта;
- LittleFS: offset `0x300000`, размер `0x100000`;
- приложение UA22+Cyrillic: **2 408 576 байт**;
- остаток в разделе: **16 256 байт**, около 15.9 KiB.

Это исторические данные конкретного устройства, не универсальная разметка
всех T-Beam. Текущая flash partition table не считывалась заново. Совпадение
model/version из USB metadata не доказывает ни разметку, ни installed binary hash.

До прошивки bridge сверить устройство, активный app partition и его реальный
размер. В сборке нужен отдельный size gate под этот раздел: успех стандартного
PlatformIO build недостаточен.
При нехватке памяти пользователь разрешил убрать кириллицу только с экрана.
UTF-8 в сообщениях, USB, радио и хранилище необходимо сохранить. Это уточнение
от 2026-09-25 заменяет прежнее требование отдельно согласовывать удаление glyphs.

Предыдущая установка была app-only; старые factory/LittleFS образы рассчитаны
на другую стандартную разметку. Новый выпуск должен явно различать app-only
update и clean-install artifacts. Каналы, owner, ключи, NVS, LittleFS и GPS
настройки сохраняются. Резервные копии flash и конфигураций не включены в новый
публичный репозиторий.

## Время GPS и RTC

В журнале 20 сентября GPS передавал неверную дату 2028 года; локальные rx_time
также оказывались в будущем. Обычное `set_time_only` было отвергнуто, поскольку
качество GPS имело приоритет над временем host. Причина ошибочной GPS-даты
не установлена; патча GPS/RTC в исходниках нет.

Впоследствии GPS отключили штатной настройкой `position.gps_mode=DISABLED`
и синхронизировали RTC PCF8563. Старый итоговый отчёт фиксирует неубывающие
timestamps и совокупную задержку/расхождение порядка 3.1–4.1 секунды; цель
менее 3 секунд не достигнута. Это не точное измерение погрешности аппаратных часов.

Для сервера сохранять отдельно raw node rx_time, host received_at и признак
достоверности времени. Не основывать retention только на потенциально неверном
rx_time. Не включать GPS обратно при установке firmware и не применять старые
time-fix scripts автоматически: они изменяют настройки и перезагружают устройство.
Политику коррекции времени ноды проектировать отдельно от S&F replay.
