# Как пользоваться MeshMemo

## Запуск и подключение

После установки по README выполните:

```powershell
meshtastic-sf-server serve --config meshmemo.toml
```

Откройте http://127.0.0.1:18765 (или IP сервера с этим портом).
Введите логин `admin` и пароль из секции `[admin]` конфигурационного файла.
Для изменения пароля отредактируйте конфиг и перезапустите сервис. В настройках выберите автоматический поиск ноды
или порт вручную и нажмите «Применить». Дождитесь статуса «Подключено · приём».
Автопоиск запоминает устройство; при нескольких неизвестных устройствах нужен
ручной выбор. Настройки подключения сохраняются между запусками.

Одновременно используйте только один сервер и одну программу, работающую с USB-нодой.
База привязана к одной ноде. Для другого устройства создавайте отдельную базу.

## Чаты

Сервер сохраняет широковещательные текстовые сообщения закрытых каналов.
Личные сообщения, телеметрия, MQTT, публичные каналы со стандартным ключом
и полученные повторы S&F в архив не входят.

Лента загружается по 100 сообщений. Кнопка «Показать более ранние» подгружает
предыдущую страницу. Во время просмотра старой истории обновление ленты
приостановлено; вернуться можно кнопкой «К последним сообщениям».
Поиск работает по тексту выбранного канала. Время — получение сервером,
отображается в часовом поясе браузера.

Вверху доступны русский, украинский и английский. Язык запоминается в браузере;
при переключении черновики настроек и открытая история сохраняются.
Имена каналов, отправителей и тексты сообщений не переводятся.
Имена нод загружаются из списка серверной USB-ноды при подключении и обновляются
по объявлениям NodeInfo. Пока имя неизвестно, показывается ID вида `!12345678`.
Когда имя получено, оно появляется и у ранее сохранённых сообщений.

## Настройки хранения

- «Сохранять новые сообщения» включает запись. При паузе новые сообщения
  пропускаются, ранее сохранённые остаются доступны.
- По умолчанию лимит — 100 000 записей. При заполнении новые записи не принимаются.
- Срок хранения 0 означает отсутствие автоматического удаления. При включении
  или сокращении срока потребуется подтверждение. Очистка происходит примерно
  раз в минуту; восстановление удалённого возможно только из прежней копии.
- Несохранённые изменения отмечены отдельно; их можно отменить.

В разделе базы доступны проверка целостности и скачивание согласованной резервной
копии. Копии содержат открытую переписку. Их серверные экземпляры остаются в папке
`backups/` рядом с базой и не удаляются автоматически. При использовании каналов
сервера отдельно сохраните файл `<имя базы>.channels.key`: в скачиваемую копию
он не входит, а без него восстановить сохранённые ключи каналов нельзя.

## Выдача истории по радио

Пока оставьте её выключенной. Это экспериментальная функция, для которой нужны
специальная USB-прошивка и проверенный клиент Meshtastic. Доступны количество
сообщений, глубина истории, пауза отправки, интервал запросов и объявления сервера.
Изменение настроек отменяет очередь. Уже принятый нодой пакет может уйти в эфир
после выключения функции.

Каналы самой USB-ноды и параметры радио меняются в приложении Meshtastic.
Дополнительные каналы добавляются в «Каналы сервера». Запись использует штатный
USB API; выдача локальных каналов требует профиль 1/2 или 1/3, серверных — 1/3.
Сквозная радиопроверка серверных каналов ещё не завершена.


Отправьте **`/history 6`** обычным сообщением в нужный закрытый канал:
сервер запросит последние 6 часов по времени получения сообщений. Примеры:
`/history 1`, `/history 24`. Часы — целое положительное число (до шести цифр);
значение выше максимальной глубины в настройках ограничивается этим максимумом
(не более 7 дней). Лимит количества выбирает последние сообщения в этом окне.
Свои сообщения запрашивающей ноды, неподдерживаемые длинные тексты и неоднозначные
повторы не выдаются. Ответ адресован запросившей ноде в формате Store & Forward.

Запрос виден участникам канала как обычное сообщение. Команды `/history`, включая
ошибочные, **не записываются в базу и не повторяются в истории**. Старые команды,
если они уже были в архиве, тоже не выдаются; существующие записи не удаляются.
Неправильные команды, повторные запросы во время ограничения и запросы при
выключенной выдаче игнорируются без ответного текста, чтобы не засорять эфир.
Пауза записи новых сообщений не отключает выдачу ранее сохранённых.

Команда работает через общий ключ именно этого канала. В личные сообщения
серверу её отправлять не нужно. Изменять прошивку клиентской ноды для отправки
команды не требуется; отображение ответа и устранение дублей зависят от версии
приложения. Кнопка Client History остаётся отдельным способом, который в проверенной
связке теряет канал из-за PKI; текстовая команда обходит эту проблему запроса.

## Каналы сервера

Откройте **Каналы сервера → Каналы**. В таблице видны имя, время последнего
сообщения и состояние записи/выдачи. «Добавить канал» и «Редактировать» открывают
модальное окно. Укажите точное имя и приватный ключ Base64 либо ссылку Meshtastic
на один канал. При редактировании пустое поле ключа сохраняет прежний ключ.
Смена имени или ключа создаёт отдельную историю; старые сообщения остаются
доступны в прежнем чате. Закрытие несохранённой формы требует подтверждения.

Можно добавить до 256 каналов на текущей частоте и с теми же параметрами LoRa,
что у USB-ноды. Слоты каналов самой ноды не меняются. Для каждого канала отдельно
включаются запись и выдача, с учётом общих настроек сервера. Оба переключателя
можно выключить. Пакеты без известного ключа для будущей расшифровки не сохраняются.

На отдельной вкладке **Управление через ЛС** можно разрешить добавление каналов
по радио. По умолчанию оно выключено. Внесите проверенные публичные PKI-ключи
администраторов в Base64 и включите разрешение. Номер или имя ноды не заменяют
проверку публичного ключа. Администратор отправляет зашифрованное PKI-ЛС USB-ноде:

```text
/channel add Private BASE64_KEY
```

Вместо примера укажите имя и ключ нужного канала. Новый канал начинает запись,
выдача истории остаётся выключенной. Команды не попадают в архив MeshMemo,
но приложение отправителя может сохранить исходящее ЛС. Для ввода ключей через
веб используйте HTTPS или SSH-туннель. Ограничения, резервирование ключей и статус
радиопроверки описаны в [руководстве по серверным каналам](server-channels.md).

Начиная с 0.1.0a7, `/history` присылает только сообщения истории без сводки
количества, окна и прошлого запроса. Если подходящих сообщений нет, ответа
не будет. Штатный Client History сохраняет свой служебный заголовок. Уже
полученные сводки в переписке телефона остаются.

## Если что-то не работает

Проверьте кабель передачи данных, выбранный порт, разрешения на USB и отсутствие
другой программы, открывшей ноду. Для проверки архива отправьте текст с другой
ноды в закрытый канал. Сервер должен оставаться запущенным. Разрывы связи могут
оставлять пропуски — гарантии восстановления всех пропущенных сообщений нет.

Админка защищена логином `admin` и паролем из конфигурации; отдельных
пользовательских аккаунтов и ролей нет. По умолчанию доступ только с самого
сервера, доступ из локальной сети настраивается явно. Не выставляйте её в интернет. Эксплуатация, служба Linux, обновления и восстановление описаны в
[deployment.md](deployment.md).
