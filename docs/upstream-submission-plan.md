## Какой результат предлагаем

Официальная прошивка получает ограниченный USB API для доверенного сервера
истории. База, выборка сообщений, настройки хранения и веб-интерфейс остаются
на компьютере. Нода проверяет разрешения и канал, формирует стандартный ответ S&F
и передаёт его в радиоочередь с исходным автором и новым внешним ID.

Режим выключен по умолчанию. Сервер и прошивка согласуют возможности; обычная
отправка сообщений по клиентскому API сохраняет существующее ограничение автора.
Цель — совместимость с официальной прошивкой после принятия и выпуска функции;
договорённости об этом с разработчиками ещё нет.

## Что нужно согласовать

1. Поддерживают ли разработчики такой режим и где должны храниться разрешение
   на него и состояние USB-сессии.
2. Как оформить protobuf API и служебные ответы S&F без универсального механизма
   отправки произвольных пакетов от чужого имени.
3. Как распределять новые packet ID и какие аппаратные проверки нужны до merge.

Поле 100, формат USF1 и привязки прототипа к плате/commit не предлагаются как
готовый стандарт. В RFC явно отмечены ещё не реализованные требования:
авторизация каждой операции, сессия с ограниченным сроком, точный результат
постановки в очередь и защита от смены конфигурации во время передачи.

## Порядок дальнейшей работы

Обращение отправлено; следующий этап — получить обратную связь по архитектуре.
После согласования подготовить отдельные изменения схемы в meshtastic/protobufs,
реализации в meshtastic/firmware и адаптера SDK/сервера. Учитывать требования
upstream к CLA; владелец аккаунта принимает их самостоятельно.

Не включать исправления original_id и USB polling повторно: они уже приняты
upstream. Не переносить пакет наших локальных патчей целиком. При подготовке
реализации начать с актуальной чистой базы develop и измерить расход памяти.

Перед заявлением о готовности требуется реальная выдача истории, отсутствие
дублей на установленном App Store-клиенте, второй закрытый канал, несколько
радиопереходов, восстановление после обрыва USB и проверки очереди/авторизации.
Текущие проверки приёма и USB-handshake этого не заменяют. Настройки и прошивка
работающей ноды при подготовке предложения не менялись.
